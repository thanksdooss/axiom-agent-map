# 엑시옴 온톨로지 (초안 0.1)

부서별로 흩어진 **유사·중복 Agent**를 찾고 왜 비슷한지 설명하기 위한 온톨로지 초안입니다. 멘토링에서 확인받기 전이라 개념 목록과 가중치는 가안입니다.

## 생각

- 원본 데이터(Text·엑셀)에는 Agent → 개발 부서 관계만 있습니다. 나머지는 설명 원문에서 LLM이 **원문 표기**를 뽑고, 별칭 사전(SKOS `prefLabel`·`altLabel`)이 표준 개념으로 맞춥니다.
- 비교 단위는 Agent가 아니라 **기능(Capability)** 입니다. 기능 하나 = 작업 유형 + 입력 데이터 + 산출물 + 업무 영역. 그래서 한 Agent의 일부만 겹치는 부분 중복도 찾습니다.
- 판정은 점수 하나가 아니라 **유형 + 근거**입니다: 중복 / 부분 중복 / 공통화 후보 / 보완 / 무관, 일치·차이 항목, 원문 근거, 검토 상태(후보 → 확정·반려).

## 파일

| 파일 | 내용 |
|---|---|
| `axiom-ontology.ttl` | 클래스 16 · 관계 22 · 속성 15, 표준 개념 6개 체계(개념 91, 별칭 185) |
| `examples.ttl` | 가상 Agent 5개 + 등록 신청 1개의 기능 프로파일, 판정 3건, 중복 군집 2개 |
| `competency-questions.rq` | 이 온톨로지가 답해야 하는 질문 6개(SPARQL) |
| `profile-extraction.schema.json` | LLM 추출 결과 형식(JSON Schema). 값은 원문 표기, 표준화는 사전이 함 |
| `tools/check_ontology.py` | 파싱 · 정의되지 않은 용어 · 별칭 충돌 · 역량 질문 실행 · 예시 점수 재계산 |

## 유사도 (가안)

- 항목 일치도: 같은 개념 1.0 · 상하위 개념 0.6 · 같은 묶음의 다른 개념 0.3 · 그 외 0
- 기능 점수 = 0.35 작업 유형 + 0.30 입력 데이터 + 0.15 산출물 + 0.10 업무 영역
- Agent 점수 = 가장 비슷한 기능 쌍의 점수 + 0.05 연동 시스템 겹침 + 0.05 사용자 겹침
- 중복: 작업 유형이 같고 입력·산출물이 0.6 이상 맞는 기능 쌍이, 기능이 적은 쪽의 모든 기능에 있음 · 부분 중복: 일부만 · 공통화 후보: 작업 유형만 같음

가중치는 정답셋(알려진 중복 사례)이 생기면 다시 맞춥니다.

## 검증

```bash
pip install rdflib
python3 ontology/tools/check_ontology.py
```
